# v1.2 Post-Release Verification Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a local post-release verification script that checks GitHub Release assets and checksum coverage for all supported platforms.

**Architecture:** Use GitHub CLI as the single GitHub integration point. Keep the verifier shell-only and test it with a fake `gh` executable so checks run offline.

**Tech Stack:** POSIX `sh`, GitHub CLI, shell test fixture.

---

### Task 1: Add Offline Tests

**Files:**
- Create: `scripts/test-verify-release-assets.sh`
- Create: `scripts/verify-release-assets.sh`

- [ ] **Step 1: Write failing tests for release verification**

Add a test script that stubs `gh release view` and `gh release download`. Cover:
- all six target assets plus checksum succeeds
- missing Release fails clearly
- missing platform asset fails clearly
- checksum missing an asset fails clearly

- [ ] **Step 2: Run test to verify it fails**

Run: `sh scripts/test-verify-release-assets.sh`

Expected: FAIL because `scripts/verify-release-assets.sh` does not exist.

- [ ] **Step 3: Implement release verifier**

Create `scripts/verify-release-assets.sh` that:
- accepts `vX.Y.Z` or `X.Y.Z`
- defaults repo to `0xlic/sush.sh`, overridable by the second argument
- requires `gh`
- checks release asset names for all six supported target triples
- locates a checksum asset whose name contains `sha256` or `checksum`
- downloads checksum asset into a temp directory
- checks each matched release asset name is present in the checksum file
- exits non-zero with clear messages for missing release, assets, checksum, or checksum coverage

- [ ] **Step 4: Run test to verify it passes**

Run: `sh scripts/test-verify-release-assets.sh`

Expected: PASS with no output.
