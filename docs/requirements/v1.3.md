# sush.sh (sush) v1.3.0 需求文档

## 版本目标

v1.3.0 聚焦 PuTTY 堡垒机调用兼容层 MVP。

目标用户是在堡垒机网页完成授权后，依赖堡垒机本地客户端拉起 PuTTY 的工作流。sush 需要提供一个可由用户主动开启的兼容层，让堡垒机“调用 PuTTY”时实际拉起 sush 本地窗口，并直接进入 SSH 会话。

## 设计原则

- 默认不启用：安装 sush 时不得自动注册、替换或伪装任何本地 SSH 工具
- 用户主动开启：必须进入 sush TUI 的 Settings 后才能启用相关功能
- 可撤销：用户应能在 Settings 中关闭该功能，并移除 sush 自己创建的兼容层配置
- 最小兼容：只兼容 PuTTY 的 SSH 启动参数，不实现完整 PuTTY 行为
- 安全优先：不绕过堡垒机权限控制，只处理堡垒机授权后传给本地工具的连接参数
- 凭证最小化：堡垒机传入的密码只用于本次连接，不保存、不记录、不复用

## 需求细则

### F1: Settings 入口与默认关闭

**规则**：
- 主界面新增 Settings 入口，快捷键在实现阶段确定，但必须在底部快捷键提示中可发现
- Settings 中提供 `PuTTY compatibility launcher` 设置项
- 该设置项默认关闭
- 未开启时，sush 行为必须与当前版本一致
- 开启、关闭和查看状态都必须在 TUI 内完成
- Settings 中必须展示当前平台对应的支持状态和下一步操作说明

### F2: Windows PuTTY shim 安装

**规则**：
- Windows 是 v1.3.0 MVP 的主要支持平台
- 用户在 Settings 中开启功能后，sush 生成或安装一个 `putty.exe` shim
- shim 路径必须在 TUI 中明确展示，供用户配置到堡垒机客户端的 PuTTY 路径中
- shim 不应覆盖系统中已存在的真实 PuTTY，除非路径是 sush 自己管理的位置
- shim 应能定位真实的 sush 可执行文件
- shim 被堡垒机调用时，应打开新的本地终端窗口运行 sush
- 优先使用 Windows Terminal `wt.exe`
- Windows Terminal 不可用时回退到 `cmd.exe`
- 关闭功能时，sush 应移除自己创建的 shim；无法自动移除时，必须给出明确的手动处理说明

### F3: 非 Windows 平台行为

**规则**：
- macOS 和 Linux 不在 v1.3.0 PuTTY shim MVP 的自动安装范围内
- 在 macOS 和 Linux 的 Settings 中，该功能不得执行 Windows shim 安装动作
- TUI 应显示当前平台不支持 PuTTY shim 自动安装，或提供手动兼容说明
- 非 Windows 平台仍可保留命令行解析能力，方便后续扩展或手动测试

### F4: PuTTY SSH 参数解析

**规则**：
- sush 必须支持 PuTTY 兼容启动入口
- 支持以下 PuTTY SSH 常用参数：
  - `-ssh`
  - `-l user`
  - `-P port`
  - `-i keyfile`
  - `-pw password`
  - `[user@]host`
- `-l user` 优先级高于 `[user@]host` 中的 user
- `-P port` 缺省时使用 22
- `-i keyfile` 映射为本次连接使用的 identity file
- `-pw password` 映射为本次连接临时密码
- 不识别或暂不支持的 PuTTY 参数应被明确拒绝或安全忽略；不得误解释为 host
- 参数解析失败时，应显示可读错误并退出，不进入主界面

### F5: 直接进入 SSH 会话

**规则**：
- PuTTY 兼容入口启动后，不进入主机列表
- sush 根据解析出的 host、user、port、identity file 和临时密码构造一次性连接目标
- 连接成功后直接进入 SSH 嵌入式终端模式
- SSH 模式下仍保留 `Ctrl-\` 切换 SFTP 能力
- 连接失败时，在本地窗口显示失败原因
- 退出 SSH 会话后，sush 退出进程，不回到主机列表

### F6: 临时密码安全边界

**规则**：
- `-pw` 传入的密码只允许用于本次认证
- 不得保存到 `hosts.toml`
- 不得保存到系统钥匙串
- 不得写入日志、状态栏历史或错误消息
- 不得出现在可复制的连接描述中
- 如果临时密码认证失败，可以回退到现有交互密码输入，但不得把临时密码持久化

### F7: 明确不支持范围

**规则**：
- v1.3.0 不支持 PuTTY saved session `-load`
- 不支持 telnet、raw、rlogin、serial
- 不支持 XShell、SecureCRT、iTerm2 伪装
- 不支持自定义 URL protocol 注册
- 不自动修改堡垒机客户端配置
- 不自动替换系统 PuTTY
- 不实现 PuTTY 的完整终端仿真、配置存储或 GUI 设置界面
- 不支持 PuTTY 端口转发参数作为 MVP 范围

## 验收重点

- 未开启 PuTTY compatibility launcher 时，sush 默认启动行为不变
- 用户能在 TUI Settings 中查看、开启和关闭 PuTTY 兼容层
- Windows 开启后能获得一个可配置给堡垒机的 `putty.exe` shim 路径
- 堡垒机调用 `putty.exe -ssh -l user -P port host` 时，能弹出本地终端窗口并启动 sush SSH 会话
- 堡垒机调用 `putty.exe -ssh user@host -P port` 时，能正确解析 user、host 和 port
- 带 `-i keyfile` 时，本次连接会尝试使用该私钥
- 带 `-pw password` 时，该密码只用于本次认证，不被保存或展示
- Windows Terminal 不存在时能回退到 `cmd.exe`
- 关闭功能后，sush 创建的 shim 被移除，或 TUI 给出明确的手动移除说明
- macOS / Linux 不执行 Windows shim 安装动作，并能显示清晰的平台限制说明
